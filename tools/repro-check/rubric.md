# Rubric: is this reproduction package ready to post?

## Checks

| Check         | Evidence                                                                                                                                                                        | Pass condition                                                                                                                                                                                                                                                                                                                                                                    | Weight   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `environment` | The repro report's environment record (`references/evidence-guide.md`), read against the issue's own stated target version/commit                                               | The report names a tool/library version (or commit), the OS/platform, and the build state, and that version either matches what the issue targets or the report explicitly says how it differs                                                                                                                                                                                    | required |
| `steps`       | The repro report's steps section (`references/evidence-guide.md`)                                                                                                               | Starting from a stated starting point (e.g. a fresh clone or a named commit), every step is a concrete command or action a stranger could run in order, ending in the exact trigger the issue describes, with an explicit expected-vs-actual stated                                                                                                                               | required |
| `behavior`    | The repro report's output/log excerpt, read against the issue's described symptom (`references/evidence-guide.md`)                                                              | The artifact shown is faithful to the report's own conclusion about the issue's exact trigger: either it reproduces the same failure signature the issue names (same error message/type, same exit code or crash mode, same observable symptom), or, when the report concludes it could not reproduce, the artifact documents a genuine attempt at the issue's same configuration/command sequence within the report's own recorded environment (any environment deviation from the issue is named, not quietly substituted - consistent with the `environment` check) and faithfully shows the failure did not occur. Fails when the artifact shows a different or adjacent failure narrated as a match, or when no artifact/vague description is given                                                                                                                                                                    | required |
| `integrity`   | The report's stated conclusion sentence, read against the artifacts it presents (`references/evidence-guide.md`)                                                                | The conclusion claims no more than the artifacts show. An honest, evidenced "could not reproduce" (real attempt: environment recorded, steps run, no match found) passes; a confident claim of reproduction that the artifact does not actually back up fails                                                                                                                     | required |
| `comments`    | The claim comment and repro comment text, read against the repo-facts block's contribution policy and any stated AI-use disclosure requirement (`references/evidence-guide.md`) | Treat every candidate comment as AI-assisted work by course convention (never read silence about AI as evidence none was used). If the repo's contribution policy requires disclosing AI assistance, the comment(s) must explicitly disclose it somewhere in their text to pass; if the policy states no such requirement (including silence), this half passes by default. Independently, the claim comment names the issue's specific behavior/version rather than a generic "I'll look into this," and promises only an investigation, an attempt, or a report - never a specific delivery date, a guaranteed fix, or a bare "please assign me" | required |

## Verdict rule

Accept if every `required` check passes. Reject if any `required` check fails. `unclear` counts as a `fail` for that check. On a claim-only draft, only `comments` (the claim-comment half) and any check whose evidence is entirely in the claim comment apply; `environment`, `steps`, and `behavior` report `unclear` per the skill's claim-only rule and are excluded from the verdict, per `SKILL.md`.
